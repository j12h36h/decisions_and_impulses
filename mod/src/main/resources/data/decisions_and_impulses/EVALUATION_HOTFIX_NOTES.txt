DAI EVALUATION / STALE-QUEUE HOTFIX

This is an overlay/full-pack hotfix for the fail-proof house+mine datapack.

Key fixes:
- fp_cycle now goes directly to fp_decide; no eat/scan/combat/target-clear shell every objective transition.
- lava recovery remains a true preemptive emergency branch without slowing normal evaluation.
- high-level material/tool gates use direct mutually-exclusive references instead of one enqueue action per possible branch.
- runtime crafting-table recognition writes state, then a fresh dispatcher snapshot chooses exactly one continuation.
- generated third-attempt sequences no longer create both a success continuation and an unconditional second fp_cycle.
- recoverable retry exhaustion no longer plays the slow impossible-camera signal. The signal remains for actual site exhaustion and unsupported material situations.
- valid crafting-table waypoints are not forgotten after access/alignment retries; they are invalidated only if the table block is actually gone.
- house construction no longer stockpiles ~90 planks. It builds incrementally and gathers only the next plank requirement; chest material acquisition is handled when the chest is actually next.
- blueprint gate chains skip already-correct nodes by direct resolution, with a barrier every 16 nodes to stay safely below resolver depth limits.

No Java changes are included. No recognition/groups/recipes/logics/menu files are replaced except the added report/notes in the full pack.
